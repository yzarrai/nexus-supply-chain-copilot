# Repository audit — 21 September 2026

## Method and conclusion

All six named repositories exist, are public, and use `main`. Verified through GitHub metadata, downloaded source snapshots, selected implementation and test files, licenses, and latest Actions run/job results. The profile descriptions are consistent with the project themes, but are not sufficient evidence of production behavior. This is a targeted reuse audit, not an exhaustive security review or a reproduction of every experiment. No repository was merged, modified, or pushed. Full upstream test suites were not executed locally; the bundled runtime lacks several upstream dependencies. Remote CI evidence below is explicitly distinguished from local tests.

Recommendation: maintain a separate NEXUS product repository and adapt small, versioned components behind contracts. `inventory-brain` is the strongest candidate for the analytical core. The initial slice uses original, dependency-free code to establish the domain contract and approval workflow before introducing these components.

## Concrete findings before reuse

1. **P1 — Simulated execution is not an ERP integration.** [Control-tower action endpoint](https://github.com/yzarrai/supply-chain-agentic-ai/blob/d58c99858df6842b2d1701d5c5d7c4d6010d0ca0/src/ui/routes.py#L383) returns a fabricated success and transaction ID, including for actions absent from its in-memory store. No durable, authenticated approval check exists inside this path. Retain only as a labeled demo; do not connect this handler to procurement.
2. **P1 — Grounding accepts changed units.** [Numeric checker](https://github.com/yzarrai/procure-rag/blob/3eedea5a0b949deb6c97a393aadf516b68e98628/src/contract_intel/generation/numeric_grounding.py) returns `None` (pass) for answer “Payment is due within 60 years.” with only source “Payment is due within 60 days.” Local isolated-function probe reproduced this; see `audit-probe.json`. The unit-match branch rechecks number presence, which is already known true. Percentage checking also relies on loose number presence. Require amount + unit + currency + subject + clause binding, and a refusal when no evidence exists.
3. **P2 — Optimization labels exceed the implementation.** [Inventory optimizer](https://github.com/yzarrai/supply-chain-agentic-ai/blob/d58c99858df6842b2d1701d5c5d7c4d6010d0ca0/src/tools/inventory_optimizer_tool.py#L76) enumerates a bounded EOQ range. It does not solve a stochastic procurement MILP, shared budget allocation, expiry-aware selection or a general multi-echelon program. Use truthful algorithm/status names and verified feasibility outputs.
4. **P2 — Retail artifacts are not operational truth.** [Policy module](https://github.com/yzarrai/retail-demand-forecasting-ml/blob/bea1e06e54e2e582845b811c0cf2f03482cbb035/src/inventory_policy.py) documents inconsistent stock semantics. Reuse statistical methods, not retail stock balances, synthetic service claims, or evaluation forecasts as production inputs.

## Licensing and dependency gate

All six have MIT license files. Any copied component must retain its applicable notice, exact upstream SHA and local modifications. MIT code licensing does not establish rights to upstream datasets, supplier contracts, trademarks or model outputs. NEXUS currently copies no upstream code. Before adoption: resolve placeholder attribution, isolate dependencies in a fresh environment, pin and scan them, reproduce relevant tests and a small benchmark, add pharmaceutical contract tests, and compare against the deterministic baseline.

Do not combine all requirements files: the projects span Python 3.10–3.12 minimums and optional ML, solver, RAG and agent stacks. Prefer a single Python 3.12 product environment, optional analytical worker extras, and one supported forecasting adapter.
